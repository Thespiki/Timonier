# Localization guide

Timonier is translated with a small gettext-style system:

- the text written in the code (the **source text**) is the translation key;
- each language has one JSON file, `src/<app>/Localization/<code>.json`, embedded in the executable;
- only the active language is loaded, once, at startup (changing the language requires a restart);
- a text without translation is displayed in the source language.

The source language is declared in `Core/Localization/Loc.cs` (`Loc.SourceLanguage`). The UI was first written in
French; the source language becomes English once all texts are extracted, and the original French is then kept
as the `fr` translation (see "Changing source texts" below).

The language setting is `auto` by default (Windows display language, English when it is not supported). Users can pick
another language in the app settings. Right-to-left languages (Arabic, Hebrew) mirror the whole window.

## API

`global using static Timonier.Core.Localization.Loc` makes these available everywhere:

| Call | Use |
| --- | --- |
| `L("Settings")` | plain text |
| `L("{0} of {1} applied", done, total)` | text with arguments (`string.Format` in the UI culture) |
| `LC("verb", "Open")` | same source text with a different meaning; the context is part of the key |
| `LP(count, "{0} file", "{0} files")` | plural; `{0}` receives `count`, `{1}`… the extra arguments |
| `{loc:L 'Settings'}` | XAML (`xmlns:loc="clr-namespace:Timonier.Core.Localization"`) |

`Loc.Culture` is the UI culture (dates, numbers). `Loc.IsRightToLeft` tells whether the UI is mirrored.
`Core/Platform/Utilities.cs` has culture-aware helpers: `Format.Bytes`, `Format.Percent`, `Format.Day`, `Format.Date`,
`Format.Duration`, `Format.Ago`.

## Rules for code

1. **Wrap every text a user can see**: page and card texts, buttons, tooltips, toasts, dialogs, tweak titles,
   descriptions, option labels, warnings and keywords, category and page titles, search entries, health check
   summaries, quick actions, `ActionResult` messages, `ValidationException` messages, `Requirement` reasons,
   elevated confirmation texts (`DescribeForConfirmation`), accessibility names.
2. **Do not wrap** identifiers, registry paths and value names, service and task names, file paths, command-line
   arguments, PowerShell scripts, URIs, winget ids, glyphs, log messages (`Log.*`) and developer-only exception messages.
3. **Literals only.** `L`, `LC` and `LP` must receive string literals, otherwise the text cannot be extracted
   (`tools/I18n` reports it as an error). Never `L(variable)`, never `L($"…")`.
4. **Whole sentences.** Never assemble a sentence from pieces: word order differs between languages.
   `"Supprimer " + n + " fichiers"` becomes `LP(n, "Supprimer {0} fichier", "Supprimer {0} fichiers")`;
   `$"Point créé le {date}"` becomes `L("Point créé le {0}", Format.Day(date))`.
5. **Placeholders** are `{0}`, `{1}`… with optional alignment/format (`{0:N0}`). A translation must use exactly the same
   placeholders (a plural `one`/`zero`/`two` form may omit `{0}`).
6. **Plurals** always use `LP`; never "fichier(s)". Languages have up to six plural forms (CLDR rules in
   `Core/Localization/PluralRules.cs`).
7. **Short ambiguous words** get a context: `LC("unité", "Go")`, `LC("état", "Ouvert")`.
8. **Dates and numbers** use `Format.*` or `x.ToString("N0", Loc.Culture)`; never a hard-coded culture such as `fr-FR`.
9. **Search keywords** are one comma-separated literal: `.Keywords(L("télémétrie, diagnostic, données"))`.
10. **Layout**: translated texts can be 30–40 % longer (German, Finnish…). Let text wrap (`TextWrapping="Wrap"`), avoid
    fixed widths on text containers and truncation of important labels.
11. **Right-to-left**: `FlowDirection` is inherited from the window, so layouts mirror automatically. Keep
    `FlowDirection="LeftToRight"` only on content that must stay left-to-right (paths, command output, IP addresses,
    registry keys). Font glyphs are not mirrored: avoid arrows that imply a direction, or pick the mirrored glyph when
    `Loc.IsRightToLeft`.

## Translation files

```json
{
  "language": "de",
  "strings":  { "Settings": "Einstellungen" },
  "contexts": { "verb": { "Open": "Öffnen" } },
  "plurals":  { "{0} files": { "one": "{0} Datei", "other": "{0} Dateien" } },
  "search":   { "on": ["einschalten", "aktivieren"], "off": ["ausschalten", "deaktivieren"], "open": ["öffnen"] }
}
```

- `strings`: source text → translation.
- `contexts`: context → (source text → translation).
- `plurals`: the source **plural** form → one translation per CLDR category needed by the language
  (`zero`, `one`, `two`, `few`, `many`, `other`).
- `search`: words that express the intent "turn on", "turn off" and "open" in the search box.
- Keep Windows feature names as Windows displays them in that language (e.g. the German Settings app wording).

## Tools

```bash
dotnet run --project tools/I18n -- extract   # writes Localization/_catalog.json (all source texts with references)
dotnet run --project tools/I18n -- check     # per language: coverage, obsolete keys, placeholder and plural errors
dotnet run --project tools/I18n -- rekey map.json
```

`rekey` replaces source texts in the code, the XAML and every language file. With `"keepOldAs": "fr"` in the map, the
old texts are written as the French translation — this is how the source language moves from French to English.

## Adding a language

1. Add it to `Languages.All` (`Core/Localization/Languages.cs`) with its native name and direction, and its plural rule
   in `PluralRules.cs` if it differs from `one`/`other`.
2. Create `Localization/<code>.json`, translate from `_catalog.json`.
3. Run `extract` then `check`, fix every error, and look at the main pages with the capture tool
   (`Capture -Page dashboard -Lang <code>` in `tools/dev.ps1`).

## Quality

The first translations were produced with AI assistance from the English and French texts and have not all been
reviewed by native speakers. Corrections are very welcome: open a pull request that edits the language file only.
